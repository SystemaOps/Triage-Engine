---

## What this service does

The triage engine accepts a patient's symptoms, vitals, uploaded report text, and physical observations. It runs them through a medical knowledge base (RAG pipeline) and an LLM, and returns a structured urgency classification with reasoning, recommended next steps, and detected red flags.

Every result is also persisted to a shared Supabase database (see [Database](#database-supabase) below).

## Running locally

### Prerequisites

- Python 3.11+
- An [OpenRouter API key](https://openrouter.ai/keys) — free tier works

### Setup

```bash
git clone https://gitlab.systemaops.com/systemaops/dta.git
cd dta
python3 -m venv .venv
source .venv/bin/activate       # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp env.example .env
# Edit .env and fill in OPENROUTER_API_KEY and SUPABASE_* values
```

### Start the server

```bash
cd api
uvicorn main:app --host 0.0.0.0 --port 8000 --reload
```

The server is ready when you see `RAG pipeline ready.` in the logs.

## API Reference

### `POST /triage` — Main endpoint

Send patient input, receive an urgency classification.

**No authentication required** on this endpoint currently (CORS is open to all origins).

#### Request body

```json
{
  "symptoms": "Severe chest pain radiating to my left arm, sweating, nausea — started 20 minutes ago.",
  "vitals": {
    "heart_rate": 118,
    "spo2": 94,
    "blood_pressure": {
      "systolic": 88,
      "diastolic": 60
    },
    "temperature": 37.2
  },
  "report_text": "ECG report: ST elevation in leads II, III, aVF.",
  "visual_notes": "Patient appears pale and diaphoretic."
}
```

| Field          | Type    | Required | Constraints | Description |
|----------------|---------|----------|-------------|-------------|
| `symptoms`     | string  | **Yes**  | 3–4000 chars | Chief complaint and symptom description. The most important field. |
| `vitals`       | object  | No       | See below   | Patient vital signs |
| `report_text`  | string  | No       | max 8000 chars | OCR-extracted text from any uploaded medical report or document |
| `visual_notes` | string  | No       | max 2000 chars | Free-text physical/visual observations (e.g. from a camera or clinician) |

**Vitals object** — all fields optional:

| Field            | Type   | Unit  | Valid range |
|------------------|--------|-------|-------------|
| `heart_rate`     | int    | bpm   | 20–300 |
| `spo2`           | float  | %     | 50–100 |
| `blood_pressure` | object | mmHg  | systolic 40–300, diastolic 20–200 |
| `temperature`    | float  | °C    | 30–45 |

#### Response body

```json
{
  "urgency_level": "emergency_referral",
  "reasoning": "The patient presents with classic STEMI symptoms — crushing chest pain radiating to the left arm with diaphoresis and nausea. Haemodynamic compromise is evident (BP 88/60, HR 118). ST elevation noted on ECG further confirms the emergency nature of this presentation.",
  "next_steps": "Call 911/999 immediately. Do not drive to hospital. Chew 300mg aspirin if not contraindicated. Have someone stay with the patient until emergency services arrive.",
  "red_flags": [
    "Chest pain radiating to the left arm",
    "Diaphoresis (sweating) with chest pain",
    "Hypotension: BP 88/60 mmHg",
    "Tachycardia: HR 118 bpm",
    "ST elevation on ECG"
  ],
  "disclaimer": "⚠️ This assessment is generated by an AI triage assistant and is NOT a medical diagnosis. It is intended to assist in prioritising care, not replace a licensed medical professional. If you are in doubt, always seek immediate medical attention.",
  "latency_ms": 8521
}
```

| Field           | Type       | Description |
|-----------------|------------|-------------|
| `session_id`    | string     | UUID for this session — pass to `POST /chat` for follow-up messages |
| `urgency_level` | string     | One of 4 levels — see table below |
| `reasoning`     | string     | 2–3 sentence clinical reasoning from the LLM |
| `next_steps`    | string     | Specific, actionable recommendation for the patient |
| `red_flags`     | string[]   | List of detected red-flag symptoms. Empty array `[]` if none. |
| `disclaimer`    | string     | Mandatory safety disclaimer — always display this to the user |
| `latency_ms`    | int        | End-to-end pipeline latency in milliseconds |

#### Urgency levels

This is the core output. Everything downstream (UI colour, TTS tone, routing logic) should be driven by this value.

| `urgency_level`        | Meaning | UI / UX guidance |
|------------------------|---------|------------------|
| `self_care`            | Minor symptoms — manageable at home with rest or OTC medication | Green. Calm tone. |
| `doctor_consultation`  | See a GP or primary care doctor within 24–48 hours | Yellow. Informative tone. |
| `urgent_care`          | Same-day urgent care clinic or ED walk-in — time-sensitive | Orange. Alert tone. |
| `emergency_referral`   | Life-threatening — call 911/999 or go to ED immediately | Red. Urgent, serious tone. |

#### For the text-to-speech teammate

**Initial triage result** — fields in priority order for speech:

1. **`urgency_level`** — use this to set the voice tone/urgency (calm → alarmed)
2. **`next_steps`** — read this out verbatim; it is written to be clear and actionable
3. **`reasoning`** — optional, can be read out if the user wants more detail
4. **`red_flags`** — can be listed if present ("Detected warning signs: ...")
5. **`disclaimer`** — should always be included at the end of any spoken output

Suggested TTS flow for `/triage` response:
```
"Your triage result is: [urgency_level spoken naturally].
[next_steps]
[If red_flags not empty]: Warning signs detected: [list red_flags].
[disclaimer]"
```

Mapping `urgency_level` to spoken phrase:
- `self_care` → "Self care at home"
- `doctor_consultation` → "See a doctor within 24 to 48 hours"
- `urgent_care` → "Go to urgent care today"
- `emergency_referral` → "This is an emergency. Call 911 or 999 immediately."

**Follow-up chat (`/chat` response)** — just read `reply` directly. It is plain prose written to be spoken. No mapping needed.

### `POST /chat` — Follow-up conversation

Continue a triage session started with `POST /triage`. The AI remembers the full prior context and can reassess urgency if the patient reports new symptoms.

#### Request body

```json
{
  "session_id": "abc-123-uuid-from-triage",
  "message": "I also have a fever now, does that change anything?"
}
```

| Field        | Type   | Required | Description |
|--------------|--------|----------|-------------|
| `session_id` | string | Yes      | The `session_id` returned by `POST /triage` |
| `message`    | string | Yes      | Patient's follow-up message (max 2000 chars) |

#### Response body

```json
{
  "session_id": "abc-123-uuid-from-triage",
  "reply": "Yes, a fever alongside those symptoms raises concern for infection or sepsis. Given your earlier vitals, I'd recommend going to urgent care today rather than waiting. If your temperature exceeds 39°C or you feel confused or short of breath, call 999 immediately."
}
```

| Field        | Type   | Description |
|--------------|--------|-------------|
| `session_id` | string | Same session ID (for chaining further messages) |
| `reply`      | string | AI response — plain text, safe to display or pass to TTS directly |

**Conversation memory:** The full history of the session is stored in Supabase and passed to the AI on every `/chat` call. Practical limit is ~30 turns before approaching the model's context window (4,096 tokens). For a triage conversation this is more than enough.

**Errors:**
- `404` — `session_id` not found (start a new session with `POST /triage`)
- `500` — LLM error

### `GET /health` — Health check

Use this to check if the server is up and the RAG pipeline is ready before sending triage requests.

```json
{
  "status": "ok",
  "rag_ready": true,
  "model": "nvidia/nemotron-3-nano-omni-30b-a3b-reasoning:free",
  "version": "1.0.0"
}
```

If `rag_ready` is `false`, the server is still initialising — wait a moment and retry.

---

### `POST /admin/rebuild-index` — Rebuild knowledge base index

Requires header: `X-Admin-Key: <ADMIN_API_KEY>`

Call this after adding new documents to the knowledge base to rebuild the retrieval index without restarting the server.

## Error responses

| HTTP status | When it happens |
|-------------|-----------------|
| `400`       | Invalid request body (missing `symptoms`, value out of range, blank string) |
| `422`       | Pydantic validation error — malformed JSON or wrong field types |
| `500`       | LLM or pipeline error |
| `503`       | RAG pipeline not ready yet (still initialising) |

All errors return `{"detail": "<message>"}`.

## Database (Supabase)

Every successful triage call is automatically saved to the `triage_sessions` table in our shared Supabase project.

**Project URL:** `https://huzogrtkxalqylwrqofk.supabase.co`

### `triage_sessions` table schema

| Column          | Type          | Description |
|-----------------|---------------|-------------|
| `id`            | uuid (PK)     | Auto-generated unique ID for each session |
| `created_at`    | timestamptz   | Timestamp of the triage call (auto-set) |
| `symptoms`      | text          | Raw symptoms string sent by the user |
| `vitals`        | jsonb         | Vitals object as JSON (nullable) |
| `report_text`   | text          | OCR report text (nullable) |
| `visual_notes`  | text          | Visual observations (nullable) |
| `urgency_level` | text          | One of the 4 urgency level strings |
| `reasoning`     | text          | LLM reasoning paragraph |
| `next_steps`    | text          | Actionable next steps |
| `red_flags`     | text[]        | Array of red flag strings |
| `latency_ms`    | int           | End-to-end latency in ms |

Teammates building dashboards, analytics, or audit logs can query this table directly via the Supabase dashboard or the Supabase client SDK. Ask Srivani for the secret key.

## Knowledge base coverage

The triage engine's RAG pipeline is backed by 10 clinical guideline documents covering:

| Category         | Conditions covered |
|------------------|--------------------|
| Cardiovascular   | Chest pain, STEMI, aortic dissection, PE |
| Respiratory      | Asthma, COPD, pneumonia, anaphylaxis with bronchospasm |
| Neurology        | Stroke, seizures, meningitis, subarachnoid haemorrhage |
| Gastrointestinal | Appendicitis, peritonitis, ectopic pregnancy, bowel obstruction |
| Vital signs      | Thresholds for HR, BP, SpO2, temperature in adults |
| Paediatrics      | Red flags for children under 12, neonatal fever |
| Mental health    | Suicidal ideation, psychosis, acute panic, serotonin syndrome |
| Sepsis           | qSOFA criteria, SIRS criteria, septic shock |
| Allergy          | Anaphylaxis, angioedema, urticaria |
| Trauma           | Major trauma, TBI, spinal cord injury, burns |

To add new guidelines, add an entry to [knowledge_base/medical_guidelines.py](knowledge_base/medical_guidelines.py) and call `POST /admin/rebuild-index`.

## Quick integration example

### Python

```python
import httpx

# 1. Initial triage
response = httpx.post("http://localhost:8000/triage", json={
    "symptoms": "I have a very bad headache, stiff neck and I am sensitive to light.",
    "vitals": {"temperature": 38.9, "heart_rate": 102}
})
result = response.json()

session_id = result["session_id"]       # save this for follow-ups
print(result["urgency_level"])          # e.g. "emergency_referral"
print(result["next_steps"])
print(result["red_flags"])

# 2. Follow-up in the same session
chat = httpx.post("http://localhost:8000/chat", json={
    "session_id": session_id,
    "message": "I also just vomited. Does that change anything?"
})
print(chat.json()["reply"])             # plain text, AI remembers full context
```

### JavaScript / TypeScript

```typescript
// 1. Initial triage
const triageRes = await fetch("http://localhost:8000/triage", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    symptoms: "I have a very bad headache, stiff neck and I am sensitive to light.",
    vitals: { temperature: 38.9, heart_rate: 102 }
  })
});
const result = await triageRes.json();
const sessionId = result.session_id;   // save for follow-ups

// 2. Follow-up in the same session
const chatRes = await fetch("http://localhost:8000/chat", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    session_id: sessionId,
    message: "I also just vomited. Does that change anything?"
  })
});
const chat = await chatRes.json();
console.log(chat.reply);               // plain text response
```
