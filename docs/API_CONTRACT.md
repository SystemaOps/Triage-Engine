## 1. System Overview

### Architecture

```
┌──────────────┐     ┌──────────────────────────────┐     ┌───────────────────┐
│              │     │                              │     │                   │
│  Kiosks      │────▶│  Firestore (Source of Truth) │────▶│  Admin Portal     │
│  Mobile Apps │     │  - patients/{id}             │     │  (React SPA)      │
│  EMR Systems │     │  - reports/{id}              │     │                   │
│              │     │  - kiosks/{id}               │     │  Real-time        │
│              │     │  - auditLogs/{id}            │     │  subscriptions    │
└──────────────┘     │  - modelWeights/{id}         │     └───────────────────┘
                     │  - notifications/{id}        │
                     │  - settings/global           │     ┌───────────────────┐
                     │  - users/{id}                │     │                   │
                     │  - organizations/{id}        │     │  Express API      │
                     │  - regions/{id}              │     │  Server           │
                     │  - facilities/{id}           │     │  (localhost:5001) │
                     │  - systemHealth/{id}         │     │                   │
                     └──────────────────────────────┘     │  /api/vector/*    │
                             │                            └───────────────────┘
                             ▼                                     
                     ┌──────────────────┐                        
                     │  Pinecone        │                        
                     │  Vector Index    │                        
                     │  (1536d, cosine) │                        
                     └──────────────────┘                        
```

### Integration Models

There are **three ways** external systems integrate:

| Model | Description | Best For |
|---|---|---|
| **Firestore Direct** | Write/read documents directly in Firestore collections. The portal uses real-time `onSnapshot` subscriptions to reflect changes instantly. | Kiosks writing patient records, EMRs pushing reports |
| **Express REST API** | HTTP endpoints for semantic vector search and index management. Requires `ADMIN_API_KEY`. | Vector search queries, file ingestion pipeline |
| **File Ingestion** | Drop JSON/CSV files into `ingestion/incoming/` directory. The file watcher daemon auto-processes them. | Legacy EMRs that export flat files |

## 2. Firestore Data Contracts (Direct Access)

### 2.1 Collection: `patients`

**Purpose**: Triage patient records. This is the core clinical data collection.

**Access Pattern**: External systems CREATE documents here. The Admin Portal subscribes to changes via `onSnapshot` and reflects updates in real-time.

**Firestore Security Rules**: See `firestore.rules` — write access requires authenticated user with `clinician` role.

#### Document Schema

```typescript
interface TriageRecord {
  id: string;                    // Auto-generated by Firestore
  patientName: string;           // Full name (PHI — access controlled)
  triageCategory: 'Self-care' | 'Doctor' | 'Urgent' | 'Emergency';
  confidence: number;            // 0.0 to 1.0
  timestamp: string;             // ISO-8601
  status: 'Registered' | 'In Triage' | 'Needs Review' | 'Escalated' | 'Resolved';
  traceEvents: TraceEvent[];     // Array of state transition audit events
}
```

#### Subcollection: `patients/{patientId}/traceEvents`

```typescript
interface TraceEvent {
  id: string;
  entityType: 'PATIENT';
  entityId: string;
  action: string;                // e.g., 'CREATE', 'UPDATE_STATUS', 'ESCALATED'
  performedBy: string;           // User email or system ID
  role: string;                  // e.g., 'DOCTOR', 'OPERATOR', 'ANALYST'
  timestamp: string;             // ISO-8601
  fromState?: string;
  toState?: string;
  reason?: string;               // Human-readable reason
}
```

#### Example Document

```json
{
  "id": "CASE-1001",
  "patientName": "Michael Chen",
  "triageCategory": "Emergency",
  "confidence": 0.98,
  "timestamp": "2026-06-08T10:00:00.000Z",
  "status": "Escalated",
  "traceEvents": [
    {
      "id": "evt-c1001-1",
      "entityType": "PATIENT",
      "entityId": "CASE-1001",
      "action": "CREATE",
      "performedBy": "kiosk_er_alpha",
      "role": "OPERATOR",
      "timestamp": "2026-06-08T08:00:00.000Z",
      "toState": "Registered",
      "reason": "Patient checked in via ER kiosk — acute chest pain reported"
    }
  ]
}
```

#### Valid Status Transitions

```
Registered → In Triage → Needs Review → Escalated → Resolved
                ↕            ↕
          (can skip)    (can skip)
```

### 2.2 Collection: `reports`

**Purpose**: Diagnostic reports associated with patients (radiology, lab, OCR, STT, symptom).

#### Document Schema

```typescript
interface DiagnosticReport {
  id: string;
  patientId: string;
  patientName: string;
  category: 'radiology' | 'lab' | 'ocr' | 'stt' | 'symptom';
  subType: string;               // e.g., 'x-ray', 'blood_panel', 'transcript'
  status: 'pending' | 'verified' | 'flagged';
  confidence: number;            // 0.0 to 1.0
  content: {
    rawText?: string;            // Free-text clinical notes (may contain PHI)
    structuredData?: Record<string, unknown>;
    aiAnalysis?: string;         // LLM-generated analysis
  };
  verifiedBy?: string;
  verifiedAt?: string;
  clinicianTriageOverride?: string | null;
  reviewNote?: string;
  clinicianAgreement?: boolean;
  disagreementCategory?: 'Hallucination' | 'Context Insufficiency' | 'Threshold Mismatch' | 'Policy Evolution' | 'Other' | null;
  createdAt: string;             // ISO-8601
}
```

#### Example Document

```json
{
  "id": "report-case-2001",
  "patientId": "CASE-1001",
  "patientName": "Michael Chen",
  "category": "radiology",
  "subType": "x-ray",
  "status": "pending",
  "confidence": 0.92,
```

## 3. Express REST API

### 3.1 Base URL

| Environment | URL |
|---|---|
| Local Development | `http://localhost:5001` |
| Production (update) | `https://api.apexhealth.internal` |

### 3.2 Authentication

All `/api/vector/*` routes require Bearer token authentication.

**Header:**
```
Authorization: Bearer <ADMIN_API_KEY>
```

**Configuration:** Set `ADMIN_API_KEY` in `.env`. If not set, authentication is skipped (local dev mode).

**Error if missing:**
```json
{
  "error": "UNAUTHORIZED",
  "message": "Missing or malformed Authorization header. Expected: Bearer <API_KEY>"
}
```

**Error if invalid:**
```json
{
  "error": "FORBIDDEN",
  "message": "Invalid API key."
}
```

### 3.3 Endpoints

#### GET /health

Liveness probe for load balancers and orchestration.

**Response 200:**
```json
{
  "status": "ok",
  "timestamp": "2026-06-08T12:00:00.000Z"
}
```

#### GET /ready

Readiness probe. Checks that required environment variables are set and optionally pings Pinecone.

**Response 200 (healthy):**
```json
{
  "status": "healthy",
  "timestamp": "2026-06-08T12:00:00.000Z",
  "checks": {
    "server": true,
    "nodeEnv": "development",
    "openaiKeySet": true,
    "pineconeKeySet": true,
    "pineconeIndex": "triage-cases",
    "pineconeReachable": true,
    "vectorCount": "42"
  }
}
```

**Response 503 (degraded):**
```json
{
  "status": "degraded",
  "timestamp": "2026-06-08T12:00:00.000Z",
  "checks": {
    "server": true,
    "nodeEnv": "development",
    "openaiKeySet": false,
    "pineconeKeySet": false
  }
}
```

#### POST /api/vector/search

Performs a semantic search across indexed triage cases. Generates an embedding via OpenAI and queries Pinecone for similar vectors.

**Request:**
```json
{
  "query": "chest pain with shortness of breath",
  "topK": 10,
  "filter": {
    "status": { "$eq": "Escalated" },
    "sourceType": { "$eq": "patient" }
  }
}
```

| Field | Type | Required | Default | Description |
|---|---|---|---|---|
| `query` | string | Yes | — | Natural language search query |
| `topK` | integer | No | 10 | Max results (1–100) |
| `filter` | object | No | — | Pinecone metadata filter |

**Response 200:**
```json
{
  "success": true,
  "query": "chest pain with shortness of breath",
  "matches": [
    {
      "id": "CASE-1001",
      "score": 0.89,
      "metadata": {
        "patientName": "Michael Chen",
        "triageCategory": "Emergency",
        "status": "Escalated",
        "confidence": 0.98,
        "timestamp": "2026-06-08T10:00:00.000Z",
        "sourceType": "patient",
        "reportCategory": null,
        "subType": null,
        "verified": null,
        "clinicianOverride": null
      }
    }
  ]
}
```

**Response 400 (invalid query):**
```json
{
  "error": "INVALID_ARGUMENT",
  "message": "'query' must be a non-empty string."
}
```

#### POST /api/vector/similar

Finds cases similar to a given case's text content. Useful for clinical decision support.

**Request:**
```json
{
  "caseText": "Patient: Michael Chen\nTriage Category: Emergency\nStatus: Escalated\nReason: ECG abnormal",
  "topK": 5
}
```

| Field | Type | Required | Default | Description |
|---|---|---|---|---|
| `caseText` | string | Yes | — | Pre-built search text |
| `topK` | integer | No | 5 | Max results (1–50) |

**Response 200:**
```json
{
  "success": true,
  "matches": [
    {
      "id": "CASE-1005",
      "score": 0.82,
      "metadata": { ... }
    }
  ]
}
```

#### POST /api/vector/index-all

Batch indexes triage cases into Pinecone. **Dual-mode operation:**

**Mode A — Explicit data in request body:**
```json
{
  "patients": [
    {
      "id": "CASE-1001",
      "text": "Patient: Michael Chen\nTriage Category: Emergency\nStatus: Escalated",
      "metadata": {
        "patientName": "Michael Chen",
        "triageCategory": "Emergency",
        "status": "Escalated",
        "confidence": 0.98,
        "timestamp": "2026-06-08T10:00:00.000Z",
        "sourceType": "patient"
      }
    }
  ],
  "reports": [...]
}
```

**Mode B — Fetch from Firestore (empty body):** Send an empty object `{}`. Requires `FIREBASE_PROJECT_ID` and service account credentials.

**Response 200:**
```json
{
  "success": true,
  "indexedCount": 14,
  "totalInIndex": 42,
  "patientsIndexed": 6,
  "reportsIndexed": 8
}
```

#### POST /api/vector/index

Indexes a single triage case into Pinecone.

**Request:**
```json
{
  "id": "CASE-1001",
  "text": "Patient: Michael Chen\nTriage Category: Emergency",
  "metadata": {
    "patientName": "Michael Chen",
    "triageCategory": "Emergency",
    "status": "Escalated",
    "confidence": 0.98,
    "timestamp": "2026-06-08T10:00:00.000Z",
    "sourceType": "patient"
  }
}
```

**Response 200:** `{ "success": true }`

#### DELETE /api/vector

Deletes vectors from the Pinecone index by their IDs.

**Request:**
```json
{
  "ids": ["CASE-1001", "report_CASE-2001"]
}
```

**Response 200:**
```json
{
  "success": true,
  "deletedCount": 2
}
```

#### GET /api/vector/stats

Returns the total vector count in the Pinecone index.

**Response 200:**
```json
{
  "success": true,
  "totalVectors": 42
}
```

## 5. File Ingestion API

### 5.1 File-Based Ingestion

For legacy systems that export flat files.

**Drop directory:** `ingestion/incoming/` (relative to project root)
**Supported formats:** JSON (array, single object, or NDJSON) and CSV
**Processing pipeline:** Parse → Validate → Index → Archive or Error

#### JSON Format

Single patient record:
```json
{
  "patientName": "Test Patient",
  "triageCategory": "Urgent",
  "confidence": 0.85,
  "status": "Registered",
  "timestamp": "2026-06-08T12:00:00.000Z",
  "traceEvents": []
}
```

Array of records:
```json
[
  { "patientName": "Patient A", "triageCategory": "Emergency", ... },
  { "patientName": "Patient B", "triageCategory": "Self-care", ... }
]
```

Pre-structured (patients + reports):
```json
{
  "patients": [...],
  "reports": [...]
}
```

#### CSV Format

```csv
patientName,triageCategory,confidence,status,timestamp
"Test Patient","Urgent",0.85,"Registered","2026-06-08T12:00:00.000Z"
```

### 5.2 Directory Layout

```
ingestion/
├── incoming/     ← Drop files here
├── archive/      ← Successfully indexed files (timestamp-prefixed)
└── error/        ← Failed files with .error.log sidecar
```

### 5.3 Error Sidecar Log

When a file fails, a `.error.log` file is written alongside it:

```
Failed at: 2026-06-08T12:00:00.000Z
Original file: test-patient.json
Reason: patientName: required string field missing or invalid.
```

### 5.4 Schema Validation Rules

See `server/services/ingestionValidator.ts` for full implementation.

**Patient required fields:**
- `patientName` (string)
- `triageCategory` — must be one of: `Self-care`, `Doctor`, `Urgent`, `Emergency`
- `confidence` (number, 0–1)
- `timestamp` (ISO-8601 string)
- `status` — must be one of: `Registered`, `In Triage`, `Needs Review`, `Escalated`, `Resolved`

**Report required fields:**
- `patientId` (string)
- `patientName` (string)
- `category` — must be one of: `radiology`, `lab`, `ocr`, `stt`, `symptom`
- `subType` (string)
- `status` — must be one of: `pending`, `verified`, `flagged`
- `confidence` (number, 0–1)
- `createdAt` (ISO-8601 string)

## 6. Authentication

### 6.1 Authentication Methods

| Method | Where Used | How It Works |
|---|---|---|
| **Firebase Auth** | Firestore direct access | SDK handles token lifecycle. Email/password or anonymous sign-in. |
| **Bearer Token** | Express REST API | `Authorization: Bearer <ADMIN_API_KEY>` header. Key set in `.env`. |
| **API Key (SDK)** | Pinecone | `PINECONE_API_KEY` — managed by Pinecone SDK. |
| **API Key (SDK)** | OpenAI | `OPENAI_API_KEY` — managed by OpenAI SDK. |

### 6.2 Role-Based Access Control

8 roles defined in `src/lib/rbac.ts`:

| Role | Portal Access | Can View Patients | Can Verify Reports | Can Manage Settings |
|---|---|---|---|---|
| `patient` | ❌ No | — | — | — |
| `caregiver` | Limited | ❌ | ❌ | ❌ |
| `clinician` | ✅ Full | ✅ Yes | ✅ Yes | ❌ |
| `kiosk_operator` | Limited | ❌ | ❌ | ❌ |
| `device_provider` | Infrastructure | ❌ | ❌ | ❌ |
| `insurance_partner` | Reports only | ❌ | ❌ | ❌ |
| `public_health` | Analytics only | ❌ | ❌ | ❌ |
| `admin` | ✅ Full | ❌ Explicitly blocked | ✅ Yes | ✅ Yes |

### 6.3 PHI De-identification

Protected Health Information is stripped before leaving Firebase:

| Field | Type | Replacement |
|---|---|---|
| `patientName` | PHI | `PATIENT_${id.substring(0,8)}` |
| `patientId` | PHI | Hashed to `pid_${sha256(id).substring(0,16)}` |
| `rawText` | PHI | Removed entirely |
| `verifiedBy` | PHI | Removed |

Implementation: `src/lib/pii.ts` — regex-based PHI pattern detection.

## 7. Error Handling

### 7.1 Error Response Format

All Express API errors follow a consistent JSON structure:

```json
{
  "error": "ERROR_CODE",
  "message": "Human-readable description of what went wrong."
}
```

### 7.2 Error Codes by Module

| Module | Error Code | Status | Cause |
|---|---|---|---|
| **Auth** | `UNAUTHORIZED` | 401 | Missing Bearer token |
| **Auth** | `FORBIDDEN` | 403 | Invalid API key |
| **Vector Search** | `INVALID_ARGUMENT` | 400 | Empty query or missing fields |
| **Vector Search** | `INTERNAL_SERVER_ERROR` | 500 | OpenAI/Pinecone API failure |
| **Index-All** | `FIRESTORE_UNAVAILABLE` | 503 | Firestore credentials missing (Mode B) |
| **General** | `NOT_FOUND` | 404 | Route does not exist |
| **General** | `INTERNAL_SERVER_ERROR` | 500 | Unexpected exception |

### 7.3 Retry Strategy

| Scenario | Recommended Retry | Backoff |
|---|---|---|
| 429 (Rate Limited) | Up to 3 retries | Exponential: 1s, 2s, 4s |
| 500/503 (Server Error) | Up to 2 retries | Linear: 5s, 10s |
| 401/403 (Auth Error) | Do NOT retry | — |
| 400 (Bad Request) | Do NOT retry | — |

### 7.4 Timeout Configuration

| Operation | Timeout | Notes |
|---|---|---|
| Vector search (embedding + query) | 30s | OpenAI + Pinecone latency varies |
| Batch index (index-all) | 60s | Depends on batch size |
| File watcher API request | 60s | `AbortController` |

## 8. Rate Limits & Performance

### 8.1 External Service Limits

| Service | Limit | Reference |
|---|---|---|
| **OpenAI Embeddings** | 3,000 RPM (tier 5) | `text-embedding-3-small`, 1536d |
| **Pinecone** | Varies by pod tier | Serverless — auto-scales |
| **Firestore** | 10,000 writes/second per database | Soft limit — can be increased |
| **Firestore** | Unlimited reads | Query-based, not document-based |

### 8.2 Performance Targets

| Metric | Target | Implementation |
|---|---|---|
| Embedding generation | < 1s per text | OpenAI batch embedding (20/batch) |
| Vector search (topK=10) | < 500ms | Pinecone serverless index |
| File ingestion (single file) | < 5s | `awaitWriteFinish` + batch embedding |
| Portal page load | < 3s | Vite bundling, lazy imports |

### 8.3 Scaling

| Component | Scales via |
|---|---|
| Express API | PM2 cluster mode on Proxmox |
| Firestore | Auto-scaling (managed by Firebase) |
| Pinecone | Serverless — auto-scales with usage |
| File Watcher | Single daemon (per VM) |
